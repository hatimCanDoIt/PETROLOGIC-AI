# PETROLOGIC AI

**AI-Powered Well Log Analysis.** Upload a LAS file → deterministic petrophysics
(Archie water saturation, density porosity, Vsh, gas-crossover detection,
contiguous HC-zone picks) → Claude reviews each zone like a senior
petrophysicist and returns a structured interpretation.

> **Important** — Results generated by PETROLOGIC AI must be reviewed and
> validated by a licensed petrophysicist before use in any operational,
> investment, or regulatory decision. See [Limitations & disclaimer](#limitations--disclaimer).

## Local development

### Prerequisites

- Python 3.11 or 3.12
- Node.js 20+ and pnpm 9+ (`npm i -g pnpm`)
- PostgreSQL 15 (or run via Docker, see below)
- An Anthropic API key (optional — the app degrades gracefully without one)

### 1. Clone & configure

```bash
git clone https://github.com/your-org/PETROLOGIC-AI.git
cd PETROLOGIC-AI
cp .env.example server/.env
cp client/.env.example client/.env
# edit server/.env — set JWT_SECRET, DATABASE_URL, ANTHROPIC_API_KEY
```

### 2. Backend

```bash
python -m venv .venv
.\.venv\Scripts\Activate.ps1            # Windows PowerShell
# source .venv/bin/activate             # macOS / Linux

pip install -r server/requirements.txt
cd server
alembic upgrade head                    # create tables
uvicorn app.main:app --reload --port 8000
```

The API is now at <http://localhost:8000>, OpenAPI docs at <http://localhost:8000/docs>.

### 3. Frontend

```bash
cd client
pnpm install
pnpm dev                                # http://localhost:5173
```

### 4. Run tests

```bash
cd server
pytest app/tests -q                     # 17 tests covering parser, engine, API
```

## Petrophysics methodology

The deterministic engine in `server/app/core/petrophysics.py` runs the
following pipeline against every uploaded LAS file. All steps are
reproducible and do not depend on Claude.

| Step | Computation                                                                                          | Where it lives           |
| ---- | ----------------------------------------------------------------------------------------------------- | ------------------------ |
| 1    | Curve extraction. Aliases for GR, RT, NPHI/PHIN, RHOZ/RHOB, PEF resolved; out-of-range values → NaN. | `auto_select_curves`     |
| 2    | **Density porosity** ϕᴅ = (ρₘₐ − ρᵦ)/(ρₘₐ − ρₗ), clipped [-0.20, 0.65].                              | `run_petrophysics` §2    |
| 3    | **Vsh (linear Larionov)** Vsh = (GR − GRclean)/(GRshale − GRclean), clipped [0,1]. Auto p5/p90.       | `run_petrophysics` §3    |
| 4    | **Effective porosity** ϕeff = ((NPHI + DPHI)/2) − Vsh · 0.35, clipped [0.001, 0.50].                  | `run_petrophysics` §4    |
| 5    | **Archie Sw** Sw = ((a · Rw)/(ϕeff^m · Rt))^(1/n); Shc = 1 − Sw; BVW = ϕeff · Sw.                     | `run_petrophysics` §5    |
| 6    | **Gas crossover** flagged where DPHI − NPHI > 0.03.                                                   | `run_petrophysics` §6    |
| 7    | **Quality mask** requires GR, RT, RHOZ, NPHI, ϕeff, Sw all finite.                                    | `run_petrophysics` §7    |
| 8    | **HC mask**: Vsh < 0.40, ϕeff > 0.08, RT > 15 Ωm, Shc > 0.35; oil vs gas split by crossover.          | `run_petrophysics` §8    |
| 9    | **Lithology from PEF**: <2.5 = SS, 2.5–4.0 = DOL, 4.0–5.5 = LS, >5.5 = uncertain/heavy.               | `run_petrophysics` §9    |
| 10   | **Zone picks**: contiguous-True runs ≥ 1 ft → zones with mean Sw/Shc/ϕ/Rt/GR/Vsh/PEF/BVW + producible. | `_find_intervals`        |
| 11   | **Statistics**: geometric-mean Rt, arithmetic means for the rest, PEF-based lithology distribution.   | `run_petrophysics` §11   |

All cut-offs (`Vsh_cutoff`, `phi_cutoff`, `Rt_cutoff`, `Shc_cutoff`,
`Sw_producible`) are user-tunable through the Parameter panel in the
report UI and the `POST /api/wells/{id}/reanalyze` endpoint.

## AI interpretation

`server/app/core/ai_interpreter.py` sends a **compact summary** (statistics,
zone metrics, data-quality indicators — never the raw log arrays) to Claude
with a system prompt that:

1. Identifies the model as a senior petrophysicist with Gulf-Coast experience.
2. Instructs it **not** to recompute the numbers — only to interpret them.
3. Constrains the response to a strict JSON schema with:
   - `well_narrative` (3–5 sentence overview)
   - `reservoir_context` (formation / depositional environment)
   - `zone_interpretations[]` (per-zone interpretation, producibility, concerns, recommended actions)
   - `data_quality_flags[]` (warning / critical)
   - `lithology_summary`
   - `overall_confidence` + `overall_confidence_reason`
   - `disclaimer` (mandatory)

The call uses `max_tokens=2000`, `temperature=0` (deterministic). If the
Anthropic key is missing or the call fails, the rest of the report continues
to work and the AI tab shows a graceful "AI interpretation unavailable" notice.

## Limitations & disclaimer

PETROLOGIC AI is an analytical aid. It is **not** a substitute for trained
human judgement. In particular:

- The deterministic engine uses **conventional Archie-only** saturation. It
  does not model dual-water, Waxman-Smits, micro-porosity, or fractured
  reservoirs.
- Lithology classification is based on PEF only. Spectroscopy, dipole-shear,
  or NMR are not consumed.
- Gas-crossover detection is empirical and fails in heavy oil, vuggy
  carbonate, or salt-saturated mud systems.
- Claude is a language model. It can produce plausible-sounding text that is
  factually wrong, especially in edge-cases or with unusual well metadata.
- All cut-offs are tunable defaults. They are not regulatory or operational
  thresholds.

> **Results generated by PETROLOGIC AI must be reviewed and validated by a
> licensed petrophysicist before use in any operational, investment, or
> regulatory decision.**
